Single purpose: View the LeetCode activity of you and a friends list you manage, with leaderboards, weekly contest points, and streak/strike tracking.

Alarms justification: The alarms permission is used by the extension's background service worker to schedule a single repeating 30-minute timer (chrome.alarms.create). On each tick the extension recomputes the user's current solving streak from already-fetched, public LeetCode data and updates the extension's toolbar badge so the streak count stays current without the popup being open. No other alarms are created and the timer only runs locally on the user's device. It is required because Manifest V3 service workers are terminated when idle and cannot use setInterval for periodic work.

Storage justification: The storage permission is used only for chrome.storage.local, entirely on the user's device; no data is sent to the developer or any third party. It stores: (1) the user's own LeetCode username, the friends they manually add, and their local settings (timezone, max strikes to check, visible tabs, streaks/strikes view, copy-button preference); and (2) a short-lived cache of public LeetCode data already fetched from leetcode.com (recent accepted submissions, per-difficulty solved counts, avatars, global ranking, weekly contest submissions) with TTLs of ~10 minutes to 24 hours. Caching is needed to make the popup load instantly and to reduce the number of requests made to LeetCode. Cached entries are keyed per username, expire automatically, and are removed when the extension is uninstalled. This is core to the single purpose (showing friends' LeetCode activity); the extension works with no account or login of its own.

Host permission justification (https://leetcode.com/*): The extension's sole purpose is to display LeetCode activity, so it must read public LeetCode data. It sends POST requests to https://leetcode.com/graphql to retrieve publicly available information about the user and the friends they explicitly add: recent accepted submissions, per-difficulty solved counts, public global ranking, and problem title/difficulty metadata. It also loads public avatar images and renders profile/problem links on leetcode.com. Only public, read-only submission/profile data is requested via the public GraphQL endpoint; no account credentials, cookies, or private/authenticated data are accessed, and no data is transmitted anywhere other than leetcode.com.

Remote code: No - all code ships in the package; only JSON is fetched from LeetCode at runtime.
